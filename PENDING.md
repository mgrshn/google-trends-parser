# Отложенные задачи парсера

## [ждёт сигнала] Расписание Trending Now переезжает в discovery

**Решение (2026-07-08):** парсер становится чисто on-demand по трендам — своего расписания опроса
Trending Now не держит. Планирование целиком у discovery: его scheduled-ингест дёргает `GET /trending`
раз в 15–30 мин, парсер отдаёт из кеша (TTL 60 мин) или скрейпит на лету, если протухло.

**Что сделать, КОГДА агент discovery поднимет scheduled-ингест и `topics` начнут наполняться:**
1. Убрать из README пример crontab `*/15 … enqueue_trending.py` (строка ~318) — либо заменить
   пометкой, что опрос трендов инициирует discovery, а не серверный cron парсера.
2. Проверить, что на сервере эта crontab-строка не прописана (если деплой уже был).
3. `scripts/enqueue_trending.py` можно оставить как ручной инструмент (разовый прогон/бэкофилл),
   но из регулярного расписания парсера убрать.

**НЕ делать раньше времени:** пока ингест discovery не крутится по расписанию, опрос трендов не должен
исчезнуть у обоих — иначе окно, где историю не собирает никто.

**Сигнал к действию:** владелец скажет «ингест discovery запущен, снимай cron».
